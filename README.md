# Fake Review Detector

A Chrome extension that flags likely fake Amazon reviews right on the product page, backed by a classifier I trained on Cohere text embeddings.

I wanted to try a full ML project end to end: train a model on real data, evaluate it honestly, and then actually ship it as something usable instead of leaving it in a notebook.

## How it works

```
Amazon page  ->  Chrome extension  ->  FastAPI server (local)  ->  Cohere API
                 badges + popup        logistic regression         embed-v4.0
                                                                   Command A+
```

1. A content script finds every review on the page and sends them to a local FastAPI server in one batch.
2. The server embeds each review with Cohere's `embed-v4.0` and scores it with a logistic regression trained on those embeddings.
3. Each review gets a badge with its probability of being real or fake. Flagged reviews have a "Why?" button that asks Command A+ to point out the signals in the text.
4. The popup lets you paste and check any review manually.

## Design decisions

- **Embeddings + logistic regression instead of fine-tuning.** Cohere's embeddings already capture a lot about writing style, so a simple linear classifier on top trains in seconds, is easy to evaluate, and doesn't need a GPU.
- **Local server instead of calling Cohere from the extension.** Anything shipped in an extension can be read by whoever installs it, so putting the API key there would expose it. The server keeps the key and the model on my machine.
- **One request per page.** The content script batches all reviews on a page into a single `/score` call, which is one embed request. Explanations are only generated when you click "Why?", since each one is a separate LLM call.
- **Explanations are told the verdict.** In early testing, Command A+ argued that reviews were fake even when the classifier said they were real. Passing the verdict and examples of both real and fake signals into the prompt fixed that.

## Results

Trained on 1,600 reviews and tested on 400 held-out reviews from the [Fake Reviews Dataset](https://www.kaggle.com/datasets/mexwell/fake-reviews-dataset) (balanced real and computer-generated).

| | Precision | Recall | F1 |
|---|---|---|---|
| Real | 0.83 | 0.86 | 0.84 |
| Fake | 0.85 | 0.82 | 0.84 |
| **Accuracy** | | | **0.84** |

I also tested it on reviews from outside the dataset:

| Review | Fake score | Outcome |
|---|---|---|
| Specific complaint with dates and device details | 28% | Correctly classified as real |
| Over-the-top praise with no details ("Five stars!") | 55% | Flagged, but barely |
| Polished, generic review in a modern AI style | 45% | Missed |

The fake reviews in the dataset were generated by an older language model, so the classifier learned that model's style rather than "suspicious writing" in general. Reviews written by current LLMs and exaggerated hype often get past it. This was the most useful finding of the project: 84% on the test set doesn't mean 84% in the real world when the data distribution has shifted.

## Challenges

**Amazon's markup changed.** My first content script used the `data-hook="review-body"` selector that most tutorials use, and it found nothing. Inspecting the live page showed that the current layout uses hashed class names (like `_Y3Itd_contain-rich-content_2IORW`) that can change on any deploy. I switched to Amazon's `data-hook` attributes (`review` and `reviewRichContentContainer`), which are stable and also work on non-English reviews. The script still checks the old selectors as a fallback.

**Badge and popup scores didn't match.** The same review scored 66% real as a badge and 64% when pasted into the popup. Copy-pasting changed the whitespace, and since embeddings depend on the exact input, the score shifted. The server now normalizes whitespace before embedding, so both paths send identical text.

**API rate limits.** The trial key is capped at 100k tokens per minute, which the first training run hit almost immediately. I added batching with backoff and retry, and cached embeddings to `embeddings.npz` so retraining doesn't repeat any API calls.

## Running it locally

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
export CO_API_KEY="your-key"
```

Download the [Fake Reviews Dataset](https://www.kaggle.com/datasets/mexwell/fake-reviews-dataset) and save it as `fake_reviews.csv` in the project folder.

```bash
python fake_review_detector.py      # trains and saves model.joblib
uvicorn server:app --port 8000      # starts the local API
```

Then load the extension: go to `chrome://extensions`, turn on Developer mode, click **Load unpacked**, and select the `extension` folder. Open any Amazon.com or Amazon.ca product page and scroll down to the reviews.

There's also a Streamlit version I built first: `streamlit run app.py`.

## Project structure

```
fake_review_detector.py   training, embedding, and explanation logic
server.py                 FastAPI backend for the extension
app.py                    Streamlit version
extension/
  manifest.json           Manifest V3 config
  background.js           service worker, forwards requests to the server
  content.js              finds reviews on Amazon and adds badges
  popup.html/js/css       manual review checker
```

## What I'd do next

- Retrain with reviews generated by current LLMs to fix the distribution shift
- Add metadata features (reviewer history, posting bursts, rating vs. text sentiment), since text alone has limits
- Compare against a fine-tuned transformer baseline
- Host the backend so the extension works without running a local server
